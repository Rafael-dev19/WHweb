# Design

<!-- impeccable:design-schema 1 -->

## Identity

Established world, refined not replaced: café-madera (#8b7355) + dorado (#c9a96e) on a near-black ground (#1a1a1a), mirrored to a warm-cream light theme (#f7f5f2) — see `public/assets/css/variables.css`. Logo and "Wooden House" name are fixed. This redesign upgrades typography, iconography, and component structure within that identity; it does not introduce a new color story.

## Typography

- `--font-display: 'Fraunces', 'Georgia', serif` — used only on customer-facing (Persuade) surfaces: hero `h1`, `.section-title`, `.about-box h2`, `.cta-section h2`, `.map-section h2`, `.social-section h3`, `.wh-guide-title`. Weight 500–600, optical sizing on. Never used in the internal staff panels (Operate mode) — those stay on `--font-body` for every heading.
- `--font-body: 'Inter', 'Segoe UI', sans-serif` — every other heading, all body text, all UI chrome, site-wide (replaces the old bare `'Segoe UI'` stack in `--font-main`). Loaded via Google Fonts (`Inter:wght@400;500;600;700`, `Fraunces:opsz,wght@9..144,500;9..144,600`) — add the same `<link>` block to any new page's `<head>`.

## Icons

Font Awesome is retired. **Lucide** (`https://unpkg.com/lucide@latest/dist/umd/lucide.js`, loaded `defer`) is the icon system everywhere: `<i data-lucide="icon-name"></i>`, converted to inline `<svg>` by `lucide.createIcons()`.

- Static pages must call `lucide.createIcons()` once on `DOMContentLoaded` (see bottom of `index.php`).
- Any script that injects icon markup dynamically **must** call it again after the DOM write — `modal-auth.js` does this via its internal `_refreshIcons()` helper; follow that pattern in new dynamic UI (panels especially).
- Sizing: Lucide icons are SVGs, so `font-size` no longer controls size. Every icon container gets an explicit `svg { width; height; stroke-width }` rule instead (see `.service-icon svg`, `.qa-icon svg`, `.why-us-icon svg` etc. in `index.css` for the pattern). Color still works automatically via `color` (Lucide strokes with `currentColor`).
- Brand logos (Google, Facebook, Instagram, WhatsApp, TikTok) are **not** in Lucide — keep them as hand-coded inline multi-color/brand SVGs, as already done in the footer social links and the new Google-sign-in callout.

## Banned pattern removed: colored `border-left` accents

The project's own `.impeccable/config.json` had ~15 accumulated suppressions of the "side-tab" rule (a colored `border-left` used as a callout/alert accent) across `styles.css`, `mi-cuenta.css`, `panel_administrador.css`, `panel_empleado.css`, `terminos.css`, `solicitudes.css` — all explicitly deferred to "Fase 11 with the design skills." This is that phase. Fixed so far on the home page's shared chrome: `.wh-info-box`, `.wh-callout` (new, replaces the inline-styled Google note), `.auth-alert.error/.success`. **Still open on the files above for later phases** — do not re-introduce `border-left` as a callout/alert convention; use a plain tinted background block instead (see `.wh-callout` in `styles.css`).

## Component patterns established on the home page

- **Repeated identical icon+heading+text card grids are the default to avoid** (craft-floor bans "same-size cards ... as the page structure"). The home page previously repeated this shape three times (services / reasons / contact). Kept it once, for `.service-card` (a genuine browsable category grid), and gave the other two sections their own structure:
  - `.why-us-panel` / `.why-us-row` — a single bordered panel split into rows (mobile) / columns (desktop) with hairline dividers, icon-badge + heading + text per row. No colored border.
  - `.contact-strip` / `.contact-strip-item` — one horizontal bar, icon/label/value per segment, hairline dividers between segments (2-column on mobile).
- Hero (`.hero`) carries its own primary actions now (`.hero-buttons`: Ver Catálogo / Pedir Cotización) instead of only living in the quick-actions bar below it.

## Phase 1 — COMPLETE (all public-facing pages)

Every public page now has the Fraunces/Inter type system, full Lucide icon system (including all JS-rendered dynamic markup — product cards, toasts, notifications, form states), and zero remaining `border-left` callout accents: `index.php`, `catalogo.php`, `detalle_producto.php`, `carrito-checkout.php`, `pago.php`, `mi-cuenta.php`, `seguimiento.php`, `solicitudes.php`, `invitacion.php`, `privacidad.php`, `terminos.php`, `acceso-denegado.php`. (`login.php` is a pure redirect stub with no UI — nothing to do there.) `grep -rl "fa-solid\|fa-brands\|fa-regular" public/*.php` returns empty.

Real bugs found and fixed along the way (not just styling):
- `.mc-noauth h2` in `mi-cuenta.css` styled a heading level (`h2`) that didn't exist in the markup (`h1`) — the rule silently never applied. Fixed the selector.
- `invitacion.php`'s logo pointed at `logo_wh.png`, a file that doesn't exist (silently hidden by its own `onerror`) — repointed to the real `logo-login.png`.
- `showNotification()` in `utils.js` (shared by carrito/checkout/push-notifications/both panels) built its toast via `textContent`, so every caller's icon markup rendered as literal escaped text, never an icon — switched to `innerHTML` + icon refresh (call sites already only pass app-authored strings, one now explicitly `escHtml`'d for the one case that interpolated a name).
- Two duplicate, independently-styled `.sesion-card-editar` rules (`carrito.css` and `solicitudes.css`) were both missing `display:flex`/icon sizing — fixed in both.

Also removed **every** `border-left` callout/alert accent site-wide on public pages, not just the home page: `styles.css`, `modal-auth.css`, `catalogo.css`, `detalle_producto.css`, `carrito.css`, `pago.css`, `mi-cuenta.css`, `solicitudes.css`, `terminos.css`. ## Phase 2/3 — COMPLETE (staff panels)

`panel_administrador.php` (82 static icons) and `panel_empleado.php` (20 static icons, shared by `empleado` + `disenador`), plus their JS (`panel_administrador.js` 136 icons, `panel_empleado.js` 77 icons, `push-notifications.js` 8 icons) are fully on Lucide. `grep -rl "fa-solid\|fa-brands\|fa-regular" public/**/*.php public/assets/js/*.js` returns empty for the whole `public/` tree, not just the panels.

- **Panels don't load `variables.css`/`styles.css`** — they're self-contained (their own `:root` token block, own Bootstrap overrides). The Lucide sizing rule and `Inter` font therefore live directly in `panel_administrador.css`/`panel_empleado.css`, not in the shared files: `svg.lucide{ width:1em; height:1em; stroke-width:1.75; }` plus `.wh-icon-spin`/`.icon-2x`/`.icon-xl` helpers for the old `fa-spin`/`fa-2x`/`fa-xl` modifier classes. `<head>` swapped the Font Awesome CDN link for `unpkg.com/lucide` (CSP already allowed `unpkg.com` and Google Fonts from Phase 1, no `.htaccess` changes needed) and added the Inter Google Fonts link.
- **Auto icon-refresh via MutationObserver**, not manual `_refreshIcons()` calls — these two JS files inject HTML in 30+ places, too many to track by hand safely. A single observer on `<body>` (debounced 30ms) at the top of each file calls `lucide.createIcons()` after any DOM mutation; this is why the "Ver" button injected by `cargarPedidosEmpleadoAPI()` (a fetch-driven table render) renders its Lucide icon with zero explicit refresh call. `showNotification()` in both files still also calls `lucide.createIcons()` inline for immediate certainty, which is redundant with the observer but harmless.
- Also fixed **the same class of icon-swap bug across the rest of the codebase**, found by grepping the whole tree instead of trusting Phase 1's page-by-page pass: `theme-toggle.js` (moon/sun), `utils.js` (full-page loader spinner), `event-delegation.js` (lightbox close), `locked-field.js` (pencil/save/spinner), `login.js` (password eye toggle, alerts — this file turned out to be orphaned, no `.php` references it, left fixed anyway since it's cheap and harmless), `app.js` (cart/menu toasts). Added a self-contained `.wh-icon-spin` (own keyframe, doesn't depend on `animations.css` being loaded) to `styles.css` for the public-site spinner case. **Phase 1's "grep returns empty" claim only checked page files, not shared JS utilities that aren't exercised by a simple page-load — re-verify with a full-tree grep, not a per-page one, before declaring any future phase done.**

Real bugs fixed (not just styling), same pattern as Phase 1:
- `panel_administrador.js`'s `kpiStockLow` KPI used `.textContent` to inject `<i>` icon markup — literal escaped text, never an icon, on the dashboard's "bajo stock" card. Fixed to `.innerHTML` (this was the bug already spotted before Phase 2/3 started).
- `push-notifications.js`: `_mostrarPromptIOS()` and `_mostrarPromptInstrucciones()`, when called directly from `initPushPrompt()` on a **freshly created** card (iOS-Safari-not-installed users, and users who already have the browser permission set to "denied"), never added the `.visible` class needed to animate out of `opacity:0` — the opt-in card was invisible (present in the DOM, unclickable-by-sight) for exactly the users who most need the manual instructions. Fixed by moving the visibility trigger into `_crearTarjetaPush()` itself so any fresh card becomes visible regardless of which view renders into it next.

**Push-notification opt-in card redesigned** per the owner's original requirement ("insista todas las veces... hasta que las active"): the insistence logic (re-prompt every login, no cooldown, "Ahora no" only dismisses for the current visit) was already implemented before this session — see `push-notifications.js` header comment. What changed is visual prominence: it was a small dismissible bottom-right toast, easy to ignore in peripheral vision; now it's a centered modal card with a dimmed/blurred backdrop, a pulsing icon ring, and a bolder gradient CTA (`push-prompt.css`). Still dismissible — the insistence is over time (reappears next login), not a session lock.

## Finish-review pass — light-theme completeness (2026-08-26)

User-reported bugs after Phase 2/3 shipped: the panel theme toggle "didn't activate" light mode, mobile scroll made the theme-toggle button disappear/clip, several boxes (cart's chosen-delivery-date summary, among others) stayed dark in light theme "on every page," and a CSP console error for `unpkg.com`'s sourcemap. All four were real, all four are fixed:

- **CSP**: `connect-src` was missing `https://unpkg.com` (only `script-src` had it) — Chrome fetches `.js.map` sourcemaps over `connect-src`. Added in both the main and `pago.php`-override CSP blocks in `public/.htaccess`.
- **Public-site hardcoded dark colors that never adapted to `[data-theme="light"]`**: this is the same root cause behind the panel complaint, the mobile-button complaint, and the "every page" complaint — components built with a *mix* of a theme token and a hardcoded hex (`background: linear-gradient(135deg, var(--color-border), #333333)`) look fine in dark mode by coincidence and go muddy/wrong in light mode, since only half the value reacts to the theme flip. Grepped `public/assets/css/*.css` for `var(--color-*), #hex` and plain hardcoded dark literals; fixed `carrito.css`'s `.fecha-resumen-box` (the delivery-date summary box named in the report), `pago.css`'s `.payment-form-section`, and — the highest-impact one, since `modal-auth.css` is shared by ~10 pages — `.auth-alert`/`.mc-alert` (error/success), `.wh-verif-banner`, `.wh-toast-verificado`, all fully hardcoded with zero light override. Converted all to the existing `--color-error/-bg`, `--color-success/-bg`, `--color-warning/-bg` tokens (already theme-correct, just unused by these components).
- **Panels: same root cause, much larger surface.** `panel_administrador.css`/`panel_empleado.css` had only 2 `[data-theme="light"]` overrides in ~1200 lines each (the token block + the logo) — every hover/active nav state (`.sidebar-item`, `.nav-links a`, `.icon-btn`, `.logout-btn`, `.filter-btn`, `.modal-close`, `.nav-close`) and several full sections (catalog card images/specs, product detail, calendar day cells `#1b1b1b`) were hardcoded dark literals, so light mode never touched them — this is why the toggle looked broken rather than just incomplete. Added proper tokens (`--chip` was already there for `panel_administrador.css`, added it plus new `--active-bg`/`--hover-text`/`--active-text` to both files' `:root`/`[data-theme="light"]` blocks) and swapped every hardcoded hex for the matching token. Also fixed a few of the same pattern living as **inline `style=""` in the JS** (`panel_administrador.js`'s two "sin imagen" product-card placeholders, the Capacidad del Taller blocked-day box) — CSS class fixes alone don't catch these since the JS never uses the class the CSS defines for that spot.
- **Mobile theme-toggle button "disappears on scroll down, reappears on scroll up"**: two real, stackable causes in `theme-toggle.css`. (1) `.theme-toggle-btn--float` had no GPU-compositing hint, while `.mobile-bottom-nav` (the same file family, `modal-auth.css`) already carries `transform: translateZ(0)` specifically to avoid this class of iOS/Android fixed-position glitch during toolbar collapse/expand — added the same treatment. (2) At ≤768px the button's `bottom: 80px` sat close enough to the `.mobile-bottom-nav` (which reaches ~56–90px depending on safe-area-inset) to risk partial occlusion under its `z-index: 9999` — raised to `bottom: calc(72px + env(safe-area-inset-bottom, 0px))` at that breakpoint so it always clears the bar with margin. Verified in Playwright at a 390×844 mobile viewport: button stays fixed and fully visible after scrolling 600px. Could not reproduce the exact iOS/Android toolbar-collapse quirk itself in Chromium emulation, so treat the GPU-compositing fix as best-practice-and-precedented rather than lab-confirmed.

**Lesson for future phases**: a component styled with `var(--token), #hardcoded-hex` in the same declaration is a stronger tell than a fully-hardcoded one — it *looks* like it's theme-aware (it has a `var()` in it) but only half-reacts. Grep for that mixed pattern specifically, not just bare hex, when auditing theme completeness. And check `[data-theme="light"]` override *density* relative to file size before trusting a theme is "done" — 2 overrides in 1200 lines is a red flag on its own, independent of any specific bug report.
